## 1. Executive summary

PDF Workbench 是一套 macOS 原生 PDF 工具，目標是用一個視窗完成大多數日常 PDF 工作：開啟、註解、整理頁面、填表、簽名、OCR、壓縮、塗黑、比對、批次處理。

它跟多數競品最大的差別不是功能數量，而是三個原則：

1. **檔案不離開這台 Mac。**
2. **沒有帳號、沒有訂閱、沒有雲端。**
3. **原生 macOS 體驗，不是包一層瀏覽器。**

第一版先供個人／內部使用，不處理金流、上架、多人協作。產品成熟後再決定是否對外發佈。

## 2. Problem statement

### 2.1 現在的問題

- **工具分散**：Preview 看 PDF 很順，但頁面整理、OCR、塗黑、轉檔要開不同工具。
- **雲端依賴**：很多 PDF 網站要求上傳檔案；對合約、身分證件、財報這類文件不可接受。
- **訂閱疲勞**：Adobe Acrobat Pro 功能完整，但價格與雲端綁定；PDF Expert 近年也走向訂閱。
- **桌機體驗退化**：不少工具是 web app 包裝，快捷鍵、拖放、列印、沙盒整合都不如原生。
- **塗黑不可靠**：很多工具只是畫黑框，底下文字還在，複製或萃取就露餡。
- **批次能力弱**：一次處理 50 份 PDF 通常要寫腳本或裝 command-line 工具。

### 2.2 我們要解決的核心問題

> 在不上傳檔案的前提下，用一個原生 Mac App 完成「開啟 → 編輯 → 保護 → 輸出」的 PDF 工作流。

## 3. Target users

### 3.1 Primary persona — 內部知識工作者

- 30–50 歲，Mac 使用者，每天處理文件。
- 常碰合約、報價、報告、掃描件、申請表。
- 會用 Preview，但遇到合併、OCR、塗黑、轉檔就沒轍。
- 在意隱私，不想把文件上傳到隨機網站。
- 願意學快捷鍵，但不想學 command line。

**代表任務**：合約簽回、報告合併、掃描存檔、個資塗黑、表格轉 Excel。

### 3.2 Secondary persona — 內部行政／法務

- 需要處理大量表單、掃描件、版本比對。
- 對「塗黑」有合規需求，必須確定資料真的移除。
- 需要批次加浮水印、頁碼、Bates 編號。

**代表任務**：一批合約加頁碼、塗黑身分證字號、比對兩版條文。

### 3.3 Tertiary persona — 開發者自己

- 想用一個可靠的工具取代零散 script。
- 在意效能、鍵盤操作、檔案格式正確性。
- 會看 log、會回報 bug、會測試邊界案例。

**代表任務**：大量 PDF 批次壓縮、OCR、轉圖片、清理 metadata。

### 3.4 非目標使用者

- 需要多人即時協作、雲端註解、審批流程的團隊。
- 需要手機／平板編輯的人。
- 需要企業級 DRM、憑證簽章、法規歸檔認證的組織。
- 需要 AI 聊天、摘要、翻譯的人。

## 4. Jobs to be done

| ID | Job | 現在的替代方案 | 痛點 |
|---|---|---|---|
| U1 | 畫重點、加註解、另存 | Preview | 註解樣式少、管理弱 |
| U2 | 合併、刪頁、排序 | Preview + 拖曳 | 多檔操作卡、頁面管理弱 |
| U3 | 掃描件 OCR | 線上 OCR / Acrobat | 要上傳、費用高 |
| U4 | 個資塗黑 | 畫黑框 / 截圖 | 文字仍可萃取，不安全 |
| U5 | 填表、簽名、回傳 | Preview / 列印簽名 | 表單 flatten 麻煩 |
| U6 | 表格轉 Excel | 手動重打 / 線上轉檔 | 版面失真、要上傳 |
| U7 | 批次加浮水印、壓縮 | 腳本 / 線上工具 | 要寫程式、不能自動化 |
| U8 | 兩版合約比對 | 人工看 / Word 比對 | PDF 不能直接比 |

## 5. Competitive landscape

| 產品 | 優勢 | 弱點 | 對我們的意義 |
|---|---|---|---|
| **Apple Preview** | 免費、原生、快、註解/簽名/表單基本可用 | 無 OCR、無塗黑、頁面整理弱、無轉檔 | 預設取代對象；日常 60% 情境 |
| **Adobe Acrobat Pro** | 功能最完整、業界標準、OCR/轉檔/簽章 | 訂閱貴、雲端綁定、介面重 | 功能標竿，但不拼全部 |
| **PDF Expert** | Mac 介面好、同步、註解強 | 進階功能訂閱、塗黑/批次有限 | UI 標竿 |
| **PDF Studio (Qoppa)** | 跨平台、功能多、一次買斷 | 介面老派、Mac 整合普通 | 功能廣度參考 |
| **Stirling PDF** | 自架、工具多、批次強 | Web UI、需 Docker、非原生 | 批次/隱私概念參考 |
| **RevPDF** | 本機、Flutter、功能完整、桌面免費 | 非原生、真文字編輯/轉檔仍有上限 | 最接近的功能對標 |
| **線上 PDF 工具** | 免費、免安裝 | 要上傳、隱私風險、廣告 | 明確的反面教材 |

### 5.1 我們的定位

> **Mac 上最可靠的本機 PDF 工作台，專注「編輯 → 保護 → 輸出」，不追求雲端與協作。**

### 5.2 差異化

1. **Native macOS**：PDFKit、Quick Actions、列印、沙盒、鍵盤操作。
2. **Privacy by default**：零上傳、零帳號、零遙測。
3. **Redaction that verifies**：塗黑後自動檢查文字萃取，不只看起來黑。
4. **Batch Flows**：把常用步驟存成流程，一次處理整個資料夾。
5. **No subscription**：內部使用沒有金流；未來若對外，採一次買斷。

### 5.3 我們不拼的

- 不拼 Acrobat 的完整 PDF 標準支援與憑證簽章。
- 不拼線上工具的「100 種格式轉換」。
- 不拼協作、雲端、AI。
- 不拼 Windows / 手機。

## 6. Product principles

1. **Local-first**：預設不連網；所有核心功能離線可用。
2. **Native**：用 macOS 原生控件與 PDFKit，不模擬行動版 UI。
3. **Non-destructive**：原檔唯讀；儲存另存或明確覆寫；破壞性操作先備份。
4. **Undoable**：所有編輯可復原；塗黑是最明確的例外，套用前要雙重確認。
5. **Keyboard-first**：常用操作有快捷鍵；可用鍵盤完成主要流程。
6. **Accessible**：VoiceOver、鍵盤焦點、高對比、減少動態。
7. **Boring reliability**：寧可功能少，不要存檔失敗或塗黑失效。
8. **No dark patterns**：沒有廣告、沒有假倒數、沒有訂閱牆。

## 7. Success metrics

### 7.1 產品指標

| 指標 | 目標 | 測量方式 |
|---|---|---|
| 日常任務完成率 | ≥ 90% 不用開其他 PDF App | 內部 dogfooding 記錄 |
| 開啟速度 | 100 MB / 500 頁 < 5 秒 | 效能測試 |
| 捲動流暢度 | 60 fps | Instruments |
| OCR 速度 | 1–3 秒/頁 | 效能測試 |
| 塗黑驗證 | 100% 通過文字萃取檢查 | 自動測試 |
| 當機恢復 | 10 秒內可恢復 | 手動測試 |
| 離線可用 | 核心流程 100% | 網路關閉測試 |
| 檔案相容 | Preview / Acrobat / Chrome 可開 | 相容性測試 |

### 7.2 工程指標

- 單元測試覆蓋核心操作（page ops、redaction、OCR、compare）。
- 每次 release 前跑完整 fixture 回歸。
- 沒有 P0/P1 未修 bug。
- 沒有已知的資料遺失風險。

### 7.3 反指標（避免）

- 功能變多但常用流程變慢。
- 為了 PDF 兼容性引入大型依賴，App 變肥。
- 為了「看起來專業」加入沒人用的面板。
- 把時間花在真文字編輯，卻讓基本存檔不穩。

## 8. Assumptions & constraints

### 8.1 Assumptions

- 使用者主要在 Mac 上工作，檔案以本機 / 網路磁碟為主。
- 多數文件 < 100 MB；500 頁以上為少數但需能處理。
- 使用者願意用繁體中文或英文介面。
- 內部使用不需要 App Store 上架、IAP、廣告。
- OCR 以 Apple Vision 為主，涵蓋中英文；其他語言後續評估。

### 8.2 Constraints

- 單人開發 + AI 輔助 + 少量測試人力。
- 第一版不引入 PDFium；先以 PDFKit 為主。
- 不處理 PDF JavaScript。
- 不保證 100% PDF 標準相容；以常見文件與主流閱讀器為準。
- 第一版只做繁中＋英文。

## 9. Research questions

在 M0 前要回答：

1. 內部最常做的 10 個 PDF 任務是什麼？排序為何？
2. 哪些任務 Preview 已經夠用？哪些一定要新工具？
3. 塗黑的需求是「看起來黑」還是「法規等級移除」？
4. 需不需要 PDF → Word/Excel？如果需要，可接受的版面失真程度？
5. 批次流程的頻率與規模（10 份 / 100 份 / 1000 份）？
6. 是否需要處理加密 PDF、簽章 PDF、XFA 表單？
7. 使用者慣用繁體中文還是英文介面？
8. 是否有多螢幕、外接掃描器、連續相機的使用情境？

### 9.1 驗證方式

- 訪談 3–5 位內部使用者。
- 收集 20 份真實 PDF（去識別化）作為 fixture。
- 觀察他們用 Preview 完成任務的步驟與痛點。
- 做一個 clickable prototype（Figma 或 SwiftUI 靜態畫面）測流程。
- 先做 M0，讓使用者試用一週，再決定 M1 範圍。

---

## 10. Positioning statement

> 對需要處理敏感 PDF 的 Mac 使用者，PDF Workbench 是一套原生、離線、不訂閱的 PDF 工作台。它讓你在同一個視窗完成註解、整理、OCR、塗黑、比對與批次輸出，而不必把文件上傳到任何地方。

---

## 11. Non-goals

- 帳號、登入、雲端同步、協作。
- 檔案上傳、雲端 OCR、雲端轉檔。
- 廣告、訂閱、IAP、試用倒數。
- iOS / iPadOS / Windows。
- AI 聊天、摘要、翻譯。
- PDF JavaScript 執行。
- 憑證簽章 / 數位簽章（第一版）。
- Office → PDF（第一版）。
- 外掛系統。
- 自動更新（第一版）。
